# 원클릭업무포털

로그인된 Edge 세션을 이용해 나이스와 K-에듀파인의 업무 입력 화면까지 이동하는 Windows 데스크톱 프로그램입니다.

## 1.4.0 — 2026-10-15

- 아침 로그인 후 연결하면 교외체험학습보고서관리를 먼저 조회하고, 기존 미상신 보고서도 종 알림으로 알려드립니다.
- 이후 10분마다 현재 조회 조건으로 확인하며 같은 보고서는 재조회·재실행 후에도 중복으로 알리지 않습니다. 보고서 알림을 누르면 해당 관리 화면으로 이동해 조회합니다.

신청서·결석신고서의 새 제출 자동 감지는 아직 연결 전입니다. 세 종류의 모의 알림에서 실제 나이스 메뉴 이동과 조회는 시험할 수 있습니다. 사용자께서 검토·승인한 안내로 [1.4.0 정식 배포](https://github.com/zeroboom92/OneClickPortal/releases/tag/v1.4.0)를 완료했습니다. 공개 설치·자동 업데이트 파일의 버전과 체크섬을 확인했고, 배포본의 안내 화면이 검토본과 일치하는 것을 확인했습니다. 기존 설치본을 트레이에서 완전히 종료한 뒤 다시 실행하면 자동 업데이트를 확인합니다.

## 설치

GitHub의 **Releases**에서 최신 `Setup.exe`를 내려받아 설치합니다.

설치형 프로그램은 시작할 때 GitHub Release의 새 버전을 확인합니다. 새 버전이 있으면 자동으로 다운로드하고 적용한 뒤 다시 실행합니다.

새 버전에서 처음 실행하면 변경 내용을 그림과 설명으로 소개하는 업데이트 안내가 표시됩니다. `이 버전 안내 다시 보지 않기`를 체크하고 닫으면 해당 버전은 다시 자동 안내하지 않습니다. 체크하지 않으면 `확인`·`설정 열기`·`X` 중 어느 방식으로 닫아도 다음 실행에서 다시 안내합니다. 다음 버전의 안내는 다시 표시합니다. 설정창과 트레이의 `업데이트 내용 보기`에서 언제든 다시 볼 수 있으며, 체크를 해제하고 닫으면 자동 안내를 다시 켤 수 있습니다. `--update-preview` 미리보기는 이 선택을 저장하지 않습니다. 안내창의 `이전 업데이트 보기`에서 과거 버전의 변경 내용을 최신순으로 확인할 수 있습니다. 처음에는 직전 버전이 선택되며, 목록에서 다른 버전을 선택하거나 본문을 스크롤할 수 있습니다. 업데이트 기록은 프로그램에 포함되어 인터넷 연결 없이도 볼 수 있습니다.

## 알림 기능 — 개발 중 (2026-10-13)

2026-10-15 로컬 개발: 교외체험학습 **보고서 미상신 알림을 실제 나이스 조회에 연결했습니다.** 아침에 로그인한 뒤 앱에서 `연결`을 누르면 나이스를 준비한 다음 **보고서관리 화면을 자동으로 열어 먼저 조회**하고, 이후 에듀파인 연결과 다른 자동 확인을 시작합니다. 보고서 화면을 미리 열어 두실 필요가 없습니다. 이후에는 **10분 간격**으로 현재 조회 조건의 서버 목록을 갱신하며 `↻`를 누르면 즉시 다시 확인합니다. 설정 저장이나 일반 업무 종료 때 불필요한 보고서 재조회는 하지 않습니다.

다른 나이스 업무 탭을 보고 있어도 열린 보고서관리의 조회는 동작합니다. 새 보고서 화면은 최소화 중 초기화가 멈출 수 있어 처음 준비할 때만 브라우저를 잠시 표시하고, 연결이 끝나면 기존처럼 최소화합니다. 이미 준비된 보고서 화면은 그대로 둡니다. 보고서관리에서 행을 체크하거나 대화상자를 연 동안에는 조회를 보류합니다. 보고서관리 탭을 직접 닫은 경우 다시 연결하면 자동으로 준비합니다.

이미 있던 미상신 보고서도 첫 조회에 알리고, 같은 보고서는 재조회·앱 재실행·모두 확인·확인 기록 삭제 후에도 다시 알리지 않습니다. 계정·학교와 보고서 자체의 학교·학년도·보고서 고유 ID를 결합한 SHA-256 지문만 따로 보관하며 학생 이름·원문·원본 식별자는 저장하지 않습니다. 현재 학급 조회 조건을 바꾸어도 이미 알린 보고서를 중복으로 알리지 않습니다. 알림 항목을 누르면 보고서관리 화면을 열며 최종 상신은 사용자가 직접 진행합니다. 이 내용은 로컬 테스트본에만 적용했고 정식 배포는 하지 않았습니다.

보고서 알림에서 `학급담임 메뉴를 찾지 못했습니다` 오류가 나던 이동을 보완했습니다. 이미 열린 보고서 탭은 제목이 화면 밖에 있어도 바로 선택하고, 탭을 닫았다면 확인된 메뉴로 다시 엽니다. 체크된 행이 있거나 조회 중이어도 기존 보고서 탭으로 이동할 수 있으며, 열린 대화상자와 취소한 화면 전환은 유지합니다. 다른 엣지 탭에서 실제 알림 항목을 열어 보고서관리 화면이 표시되는 것까지 확인했습니다.

학부모가 교외체험학습 신청서나 결석신고서를 제출해도 담임이 매번 신청 목록을 열어 확인하기는 번거롭고, 새 제출을 놓치기 쉽다는 문제에서 시작한 기능입니다. 새 결재문서와 학생의 새 신청을 먼저 알려주고, 바로 확인하지 못한 알림은 나중에 모아 확인할 수 있도록 개발합니다. 알림 UI가 크고 복잡하다는 사용자 의견에 따라 **설정 옆 작은 종과 매우 간단한 알림창**으로 다시 구성했습니다.

- 첫 개발 범위는 **에듀파인 화면에 표시된 결재대기 건수의 증가 감지**입니다. 연결 후 처음 읽은 기존 건수는 기준값으로 삼아 새 알림을 만들지 않고, 이후 증가한 경우 Windows 알림 팝업과 알림 목록에 남깁니다.
- 설정 옆 28px 종을 누르면 작은 알림창이 열립니다. 미확인 알림이 있으면 종에 숫자 대신 빨간 점을 표시합니다. 알림창은 `알림` 제목·`모두 확인`·`×`와 스크롤 목록으로 구성하며, 각 항목에는 짧은 내용과 시간, 미확인 점만 표시합니다. 항목을 누르면 확인 처리하고 연결 가능한 관련 업무 화면을 엽니다. 창 밖 클릭·Esc·`×`로 닫습니다.
- 알림 기록과 확인 상태는 PC에 최신 300개까지 보관하며 프로그램을 다시 실행해도 유지합니다. 학생 이름·문서 원문·로그인 정보는 알림 기록에 저장하지 않습니다.
- **교외체험학습 신청서·결석신고서의 새 제출 자동 알림은 아직 실제 수집에 연결하지 않았습니다.** 위에서 설명한 보고서 미상신 자동 감지와 별도 범위입니다. 두 종류의 알림 클릭 시 실제 관리 메뉴 열기와 조회는 아래 테스트본에 연결했습니다.
- 2026-10-15 실제 원클릭의 종에 신청서·결석신고서·보고서 모의 알림을 각각 1건 넣는 테스트본을 추가했습니다. `publish-test-student-notification-20261015/StartPreview.cmd` 또는 `--student-notification-preview`로 실행합니다. 기존 로그인된 Edge에 연결하고 `모의 알림` 창을 앞으로 표시합니다. 항목을 누르면 해당 나이스 관리 메뉴로 이동해 현재 조건으로 조회하며, 종으로 다시 열어 다른 항목도 시험할 수 있습니다. 알림은 모의이고 조회는 실제 나이스입니다. 모의 기록은 별도 임시 저장소를 사용하며 실제 알림 기록은 유지합니다. 세 항목 모두 실제 클릭 흐름에서 메뉴 선택과 서버 조회 성공을 확인했습니다. 최종 상신은 직접 진행합니다.
- 교외체험학습 확인 경로: 나이스 상단 `학급담임` → `교육활동신청관리` → `교외체험학습관리` → `교외체험학습신청서관리` → `조회`. 사용자 확인에 따르면 진행상태 `접수-완결`은 완료된 건입니다. 완료된 건과 새 제출을 구분하는 기준으로 기록합니다.
- 결석신고 확인 경로: 나이스 상단 `학급담임` → `교육활동신청관리` → `출결관리` → `결석신고서관리` → `조회`.
- 학생 신청 목록은 **조회 전 화면을 반복 읽는 것만으로 신규 서버 제출을 감지할 수 없습니다.** 신청서·결석신고서 알림 클릭의 메뉴 이동과 조회 완료는 검증했지만, 새 제출 자동 감지에는 목록의 고유키·처리 상태와 최초/재시작/중복 정책을 추가로 연결해야 합니다. 현재 신청/결석 기본 감지 구조는 첫 조회와 재시작 후 첫 목록을 알림 없이 기준선으로 잡습니다.
- 결재 건수 방식은 문서가 하나 빠지고 하나 들어와 총건수가 같게 유지되는 경우 새 문서를 감지하지 못합니다. 프로그램 실행·브라우저 로그인·앱 연결이 유지되고, 에듀파인 화면의 숫자 자체가 갱신되어야 알림에 반영됩니다. 서버의 새 문서 목록을 별도로 조회하는 방식은 아닙니다.
- 로그인·인증서 선택과 최종 상신·결재는 사용자가 직접 진행합니다. 이 항목은 개발 중인 범위이며 정식 업데이트 배포 기록과 구분합니다.
- 앱의 로그인 버튼, 명시적 재연결 또는 확인된 에듀파인 세션 만료 후에는 감지 기준을 다시 잡습니다. 앱에서 관측하지 못한 동일 탭의 직접 계정 변경은 구별하지 못하므로, 다른 계정으로 로그인한 뒤에는 다시 연결합니다.
- 테스트본: `publish-test-notifications-20261013-r2/StartPreview.cmd`. 기존 설치본과 테스트본을 트레이에서 `완전히 종료`한 뒤 실행하고 작은 종을 눌러 확인합니다. 자동 업데이트는 하지 않고 알림 기록은 설치본과 별도로 보관합니다. 기존 설정은 설치본과 공유합니다.

- 예산은 사업관리카드 조회 화면을 열고 현재 조건으로 조회를 한 번 실행합니다. 별도25초 화면 확인 때문에 이동 실패 안내가 뜨던 흐름을 개선했습니다.
- 숨겨진 종료 문구 때문에 정상 에듀파인 화면에서도 재로그인 안내가 뜰 수 있던 문제를 수정했습니다.
- 첫 실행 안내와 설정·트레이의 업데이트 내용 보기를 새 기능 설명으로 바꿨습니다.

## 사용 순서

1. 프로그램에서 `로그인`을 누릅니다.
2. 열린 Edge에서 업무포털 로그인과 인증서 인증을 직접 완료합니다.
3. 프로그램에서 해당 Edge 창을 선택하고 `연결`을 누릅니다.
4. 프로그램이 업무포털에서 `나이스`와 `에듀파인` 항목을 찾아 미리 열고 브라우저를 최소화합니다. 항목을 찾지 못하면 선택한 교육청의 공식 주소로 새 탭을 엽니다.
   - 업무포털 공지창이 열려 있으면 `1주일동안 열지 않기`를 선택하고 자동으로 닫습니다.
   - 나이스와 K-에듀파인 공지사항 안내창이 열려 있으면 닫기 버튼을 찾아 자동으로 닫고 업무 이동을 계속합니다.
   - 나이스에서 `정보보호를 위해 시스템을 종료합니다` 안내창이 나타나면 `확인`을 누르고 세션 종료 상태로 안내합니다. 실행 중이던 업무 요청은 재로그인 후 연결하면 이어서 실행합니다.
   - 공지창이나 닫기 버튼을 찾지 못해도 오류로 중단하지 않고 다음 준비 단계로 진행합니다.
   - 로그인 창을 열기 전에 전용 Edge 프로필에서 선택한 교육청의 업무포털·나이스·K-에듀파인에 로컬 네트워크 접근을 허용합니다. WXSClient 실행 허용은 K-에듀파인 주소에 적용합니다.
5. `나이스`, `복무`, `출장`, `에듀파인`, `기안`, `품의`, `결재`, `예산` 버튼으로 필요한 화면을 엽니다.
   - 나이스에서 다른 업무 탭을 사용 중이어도 `복무`와 `출장`은 기본메뉴로 전환해 대상 화면을 찾으며, 기존 업무 탭은 닫지 않습니다.
   - `결재`는 업무관리의 결재대기 목록을 엽니다. 하단에 해당 업무 탭이 이미 열려 있으면 그 탭을 선택합니다. 최종 결재나 일괄결재는 실행하지 않습니다.
   - `예산`은 학교회계 → 사업관리에서 사업별 예산현황을 확인할 수 있는 사업관리카드 조회 화면을 엽니다. 표시된 메뉴 중 `사업별예산현황`, `사업관리카드(담당)`, `사업관리카드(현액)`, `사업관리카드` 순으로 찾습니다. 화면이 준비되면 현재 조건으로 `조회`를 한 번 누릅니다. 활성 화면의 조회 버튼을 확인할 수 없으면 자동 조회를 건너뛰고 안내합니다.
6. 설정에서 세션 자동 연장을 켜면 업무포털의 `세션 시간 초기화` 버튼과 실제 `/bpm_lgn_lg00_102.do` 요청 완료를 확인합니다. HTTP 성공 응답을 받은 경우에만 업무포털 연장 성공으로 기록하며, 완료 여부를 알 수 없는 요청은 다시 보내지 않고 화면 확인을 안내합니다.
   - 나이스는 사이트 자체 jQuery의 `/sessionExtension.do` 요청과 프로그램 요청을 하나의 진행 상태로 공유해 중복 요청을 막습니다. 연장 요청이 2분 넘게 멈추면 기존 요청을 취소하고, 취소 완료를 확인한 뒤 1분 후 재시도합니다. 취소 완료가 불명확하면 중복 전송하지 않습니다. 실제 `Y` 응답을 확인한 경우에만 화면 타이머를 초기화합니다.
   - K-에듀파인은 Nexacro의 공식 `/naa/cmmn/cmmn/sessionCheck.do` 요청과 콜백을 사용하고, 서버 생존 응답이 `Y`일 때만 사용시간을 초기화합니다. 5분 넘게 요청 종료를 확인할 수 없으면 자동 재전송을 멈추고 화면 확인을 안내합니다. 나이스와 K-에듀파인의 `N` 응답은 즉시 재로그인 상태로 안내합니다.
   - 프로그램 실행 중 Windows의 자동 유휴 절전을 막습니다. 전원 계획은 변경하지 않으며, 사용자가 직접 실행하는 절전과 화면 잠금은 그대로 동작합니다.
   - 업무포털·나이스·K-에듀파인을 각각 확인합니다. 한 시스템이 로그아웃되거나 응답하지 않아도 나머지 시스템의 감시와 브라우저 연결은 계속 유지합니다. 안내창은 비모달로 표시되므로 닫지 않아도 다음 점검이 계속됩니다.
   - 서버의 보안 정책에 따른 로그아웃까지 무효화하지는 않습니다. 재로그인이 필요하면 해당 시스템만 대기 상태로 두며, 실제 복구를 확인한 뒤 대기 중인 업무를 한 번 이어서 실행합니다.
7. 다른 지역 사용자는 설정에서 소속 교육청을 선택한 뒤 새 로그인 창을 엽니다.
   - 저장한 소속 교육청은 프로그램을 종료했다 다시 실행해도 유지됩니다.
8. 내용을 확인하고 입력한 뒤 최종 상신 또는 결재 요청은 사용자가 직접 실행합니다.

## 결재대기 배지 MVP (로컬 테스트본)

- 결재 버튼 오른쪽 아래 모서리에 빨간 원과 흰색 숫자로 화면의 결재대기 건수를 표시합니다. r8에서는 글자를 가운데로 복원하고 숫자 원을14px(96 DPI)로 줄였습니다. 상단 모드에서는 아래로 조금 걸치고, 두 행인 별도 창에서는 아래 예산 버튼을 가리지 않도록 모서리 안에 맞춥니다. 확인된 0건은 `0`, 100건 이상은 `99+`로 표시하며 마우스를 올리면 정확한 건수와 확인 시간을 볼 수 있습니다. 숫자를 눌러도 결재 버튼과 같이 동작합니다.
- 연결 직후와 업무 이동 완료 후 건수를 읽습니다. 이후 연결한 에듀파인 창을 사용 중이면 약 5초, 최소화·다른 창·다른 탭을 사용하는 동안에는 1분 간격으로 확인합니다. 활성 여부는 연결창의 전경·최소화 상태와 `에듀파인` 창 제목으로 판정합니다. 세션 자동 연장 설정을 꺼도 건수 확인은 동작합니다.
- 5초 확인은 상단 숫자 영역만 읽습니다. 전체 화면의 대체 표기 탐색은 초기·수동 확인과 1분 주기에만 수행합니다. 이전 읽기나 다른 업무가 진행 중이면 자동 확인을 건너뛰어 요청을 쌓지 않습니다.
- `↻` 버튼으로 브라우저 창 목록과 결재 건수를 바로 다시 확인할 수 있습니다. 숫자를 읽지 못하면 결재 버튼의 툴팁에 화면 없음·여러 탭·건수 확인 불가를 구분해 안내합니다.
- 브라우저를 앞으로 가져오거나 페이지를 새로고침하지 않습니다. **서버의 새 문서 수를 별도로 조회하지 않으며, 에듀파인 화면 자체에 갱신된 숫자를 읽습니다.**
- `결재대기(문서)` 또는 `결재(긴급)` 요약을 찾지 못하거나, 읽기 실패·로그아웃·연결 해제·여러 에듀파인 탭으로 대상이 불명확한 경우에는 숫자를 숨깁니다. 2분 넘게 다시 읽지 못한 이전 건수도 숨깁니다. 배지가 없다는 것은 0건을 의미하지 않습니다.
- 상단 모드에서는 결재·예산이 업무 버튼 가장 오른쪽에 나란히 표시됩니다. 별도 창에서는 오른쪽 마지막 업무 열에 결재·예산을 위아래로 배치합니다. 결재는 연보라색, 예산은 살구색입니다. r7부터 결재·예산 너비를 출장·품의와 같게 맞췄으며, 높이와 버튼 사이 1px 간격을 유지합니다. 96 DPI 기준 창 크기는 각각 800×40, 558×66입니다.
- 실행: `publish-test-approval-budget-20261008-r9/StartPreview.cmd`. **기존 설치본과 이전 테스트본을 모두 트레이 메뉴의 `완전히 종료`로 종료한 뒤 실행합니다.** 새 테스트본은 확인된 기존본이 실행 중이면 시작을 중단하고 안내합니다. r6부터 테스트본의 `X`는 감시 작업까지 종료합니다. 자동 업데이트는 실행하지 않으며 설정은 설치본과 공유합니다.
- r3에서는 사용자가 첨부한 화면의 상단 `결재(긴급) 5(0)`처럼 공람·문서진행 숫자가 같은 영역에 있어도 결재 전체 건수인 `5`를 읽도록 보완했습니다. 긴급 건수는 합산하지 않으며, 검색 결과 건수보다 상단 결재 요약을 우선합니다.
- r3의 건수 표시는 사용자가 정상 동작을 확인했습니다. r4에서는 결재대기 제목과 기관 정보가 별도 요소인 화면도 인식하며, 검색 항목 또는 문서 표를 함께 확인합니다. r7에서는 뒤에 남아 있는 화면만으로 이동 완료를 판단하지 않고, 이미 열린 결재대기 업무 탭을 실제로 선택합니다.
- r9에서는 결재대기 탭 또는 메뉴를 클릭한 직후 브라우저를 표시합니다. 기존 탭 선택 뒤3초, 메뉴 선택 뒤5초 동안 문서 표 모양을 다시 확인하던 대기를 제거했습니다. 메뉴를 찾지 못한 경우, 통신 오류, 세션 만료는 별도로 처리합니다.
- 예산은 메뉴 선택 뒤25초 동안 별도의 화면 제목/표 준비판정을 기다리던 단계를 제거했습니다. 사업관리카드 안의 활성 조회 버튼만 최대5초 확인하고 한 번 클릭하며, 버튼을 확인하지 못해도 브라우저를 표시하고 화면 확인을 안내합니다. 단순 화면 확인 불일치로 이동 실패 팝업을 띄우지 않습니다.
- r6에서는 숨겨진 화면/iframe의 사용시간 종료 문구로 만료를 잘못 판단하는 문제를 수정했습니다. 표시 시간 `0:00`만 있으면 공식 서버 응답을 새로 확인합니다. 서버가 응답해도 사용시간 초기화를 확인하지 못하면 화면 확인 상태로 안내하며, 보이는 종료 안내나 서버 종료 응답은 재로그인 상태로 처리합니다.
- 자동 테스트와 Debug 빌드, 두 배치의 로컬 WinForms 배지 표시·위치·중복 실행 방지 및 테스트본 X 종료 검증이 통과했습니다. 빠른 읽기의 탐색량 감소는 큰 표를 넣은 재현 화면에서 검증했으며 실제 브라우저 CPU 측정은 아닙니다. 결재 후 에듀파인 상단 숫자 자체가 갱신되어야 배지에도 반영됩니다. 1.2.0 정식 업데이트에 포함됩니다.

## 인증서 프로그램 설치 안내가 반복되거나 로그인 창이 열리지 않을 때

일반 Edge에서는 로그인이 되지만 원클릭의 `로그인`으로 연 Edge에서는 설치 안내가 나타나는 경우, 전용 프로필의 사이트 권한부터 확인합니다. 두 Edge 프로필의 사이트 권한은 별도로 저장됩니다. [교육부 행정전자서명인증센터 안내](https://www.epki.go.kr/boardCnts/view.do?boardID=1000001&boardSeq=1104496&lev=0&m=0502)에서도 로컬 네트워크 연결을 차단하면 보안 프로그램이 정상 설치되어 있어도 인증서 로그인 창이 실행되지 않을 수 있다고 설명합니다.

`요청(기본값)`은 차단 상태가 아닙니다. 정상 브라우저에도 같은 값이 표시될 수 있으므로 이 설정만으로 원인을 확정하지 않습니다. 아래의 명시적 허용과 새로고침은 권한 문제인지 확인하는 단계입니다. 허용해도 같으면 제보자 PC의 동일 업무포털 주소에서 일반 Edge와 전용 Edge를 비교하고, 로그인 직후 브라우저 오류 및 인증서 모듈의 통신 방식을 확인해야 합니다.

1. **원클릭에서 연 Edge 창**의 업무포털 페이지에서 주소창 왼쪽 사이트 정보 버튼을 누릅니다.
2. `이 사이트에 대한 사용 권한`에서 `로컬 네트워크 액세스`를 `허용`으로 바꿉니다. Edge 버전에 따라 로컬 네트워크와 이 장치의 앱·서비스 접근 항목이 나뉘어 있으면 해당 항목도 확인합니다.
3. 업무포털 페이지를 새로고침한 뒤 로그인 버튼을 다시 누릅니다.
4. 여전히 창이 열리지 않으면 주소창의 팝업 차단 표시를 확인하고, 업무포털 주소에 한해 팝업을 허용한 뒤 다시 시도합니다.

2026-10-07 로컬 수정본은 로그인 전에 업무포털 권한도 준비합니다. 권한 변경이 필요한데 전용 Edge가 실행 중이면 설정 파일을 덮어쓰지 않고 재시작 안내를 표시합니다. 원클릭의 `로그인`으로 연 Edge 창을 모두 닫고 다시 `로그인`을 누르거나, 현재 창에서 위 순서로 직접 권한을 설정합니다. 이 수정본의 제보자 PC 실제 로그인과 정식 배포는 아직 완료하지 않았습니다.

## 지역 및 창 설정

- 프로그램은 작업표시줄 버튼 대신 오른쪽 알림 영역(시스템 트레이)에 아이콘으로 표시됩니다. Windows 설정에 따라 `^` 숨겨진 아이콘 목록에 들어갈 수 있습니다.
- 설치본의 `X` 또는 Alt+F4는 창만 숨깁니다. 연결과 설정된 세션 자동 연장은 유지되며, 자동 유휴 절전 방지도 계속 적용됩니다. r6 이후 로컬 테스트본에서는 `X` 또는 Alt+F4로 프로그램과 감시 작업을 종료합니다.
- 트레이 아이콘을 클릭하거나 프로그램을 다시 실행하면 기존 창이 열립니다. 완전히 종료하려면 트레이 아이콘을 오른쪽 클릭하고 `완전히 종료`를 선택합니다.
- 서울·경기·경남·부산·대구·대전·경북·세종·울산·인천·광주·전남·전북·충남·충북·강원·제주를 지원합니다.
- 선택한 교육청에 맞춰 업무포털, 나이스, K-에듀파인 주소를 자동으로 사용합니다.
- 기존 사용자와 설정값이 없는 사용자의 기본 교육청은 전북입니다.
- 설정의 `표시 방식`에서 미리보기 그림을 보고 `상단에 숨기기`와 `별도 창으로 띄우기` 중 하나를 동그란 선택 버튼으로 고를 수 있습니다. 그림이나 카드 영역을 눌러도 선택되고, 선택한 카드에 파란 테두리가 표시됩니다. 저장 즉시 전환되며 다음 실행에도 선택값을 유지합니다. 선택값이 없으면 상단 방식으로 시작합니다.
- 상단 방식은 평소 메뉴바가 접혀 있고 `▼ 업무포털` 열기 버튼은 항상 보입니다. 열기 버튼에 마우스를 올리면 클릭 없이 한 줄 메뉴바가 펼쳐집니다. 메뉴바와 손잡이에서 마우스가 벗어나면 2초 기다린 뒤 메뉴바가 다시 접히고 열기 버튼만 남습니다. 기다리는 중에 마우스가 돌아오면 접기를 취소합니다. 드래그·목록 선택·설정·키보드 조작 중에는 자동 접기를 일시 정지합니다. `▲ 접기`나 Esc로 직접 접을 수도 있으며, 직접 접거나 손잡이를 드래그한 직후에는 마우스를 밖으로 옮겼다가 다시 올려야 자동으로 펼쳐집니다.
- 상단 메뉴바의 왼쪽 로고 또는 손잡이를 잡아 좌우로 이동할 수 있으며 위치를 저장합니다. 별도 창은 이전 2행 배치로 표시되며 빈 공간을 드래그해 이동할 수 있습니다. 별도 창의 저장 위치를 복원하고, 위치가 없거나 화면 밖이면 우측 하단에 표시합니다.
- 설정의 `배경 불투명도` 슬라이더를 움직이면 메뉴바 배경에 실시간으로 미리 반영합니다. 0%는 배경 완전 투명, 100%는 불투명이며 버튼·글자·브라우저 선택 상자·결재 건수는 항상 선명하게 유지합니다. `저장`을 누르면 저장하고 취소·Esc·X로 닫으면 원래 값으로 돌아갑니다. 미리보기 중에는 메뉴바를 펼쳐 둡니다. 별도 창의 배경이 완전히 투명할 때는 제목 글자를 잡아 이동합니다.
- 트레이의 `상단 숨김 · 슬라이드` 메뉴에서도 같은 표시 방식을 전환·저장할 수 있습니다.
- `프로그램을 항상 위에 표시`는 별도 창 방식에서 설정할 수 있으며 기본값은 꺼짐입니다.
- 메인 작업창과 설정창은 Windows 모니터별 DPI 배율에 맞춰 크기와 글자를 함께 조정합니다.
- 서로 다른 배율의 모니터 사이로 창을 이동해도 화면 안에 보이도록 위치를 보정합니다.

## 안전 원칙

- 로그인과 인증서 선택은 사용자가 직접 수행합니다.
- 프로그램은 최종 상신·결재 요청 버튼을 자동으로 누르지 않습니다.
- 로컬 네트워크 권한은 원클릭 업무포털의 전용 Edge 프로필 안에서 선택한 교육청의 업무포털·나이스·K-에듀파인 주소에 적용합니다. `wxsclient` 실행 허용은 K-에듀파인 주소에만 적용합니다.
- 로그인 정보, 인증서 암호, 개인정보와 세션 토큰을 저장하지 않습니다.
- 사용자 수 집계는 로그인 없이 익명 설치 식별자의 SHA-256 해시와 앱 버전만 전송합니다.
- 기본 사용 통계는 하루 한 번, 현재 사용자 신호는 한국 시간 오전 7시~11시에만 30분 간격으로 전송합니다.
- 이름, 이메일, 학교, 나이스·K-에듀파인 화면 내용은 사용 통계에 포함하지 않습니다.
- 익명 사용 통계는 설정에서 언제든지 끌 수 있습니다.

## Firebase 사용 통계

Firebase 프로젝트 ID는 `oneclickportal`입니다. Cloud Function은 새 설치 수와 날짜별 활성 설치 수를 Cloud Firestore에 기록합니다.

설정창에는 항상 `현재 n명의 사용자가 원클릭 업무포털을 사용 중입니다`로 표시합니다. 내부 집계는 오전 7시~11시 동안 최근 40분 인원을 사용하고, 그 밖의 시간에는 가장 최근 오전 11시 집계값을 유지합니다.

- 전체 설치 수: `usageStats/global.totalInstallations`
- 날짜별 활성 설치 수: `usageDaily/{yyyy-MM-dd}.activeInstallations`
- 익명 설치별 최초·최근 실행: `anonymousInstalls/{SHA-256 해시}`

로그인 없는 집계이므로 한 사람이 여러 PC에 설치하거나 레지스트리를 초기화하면 별도 설치로 계산됩니다. 또한 공개 HTTP 엔드포인트 특성상 이 수치는 정확한 개인 수가 아니라 활용 추세를 보는 추정치입니다.

백엔드 테스트와 배포:

```powershell
cd .\functions
npm install
npm test
cd ..
npx firebase-tools deploy --only firestore:rules,functions
```

## 로그

현재 수정본은 Windows 잠금·해제와 절전·복귀, 시스템별 세션 확인 결과, 공식 연장 요청의 HTTP 또는 서버 응답 상태를 기록합니다. 프로그램이 실행되는 동안 Windows `SYSTEM_REQUIRED` 요청으로 자동 유휴 절전을 억제하고 종료할 때 해제합니다. 사용자가 직접 실행하는 절전과 화면 잠금, 조직의 전원 정책 및 서버의 강제 로그아웃 정책은 그대로 적용됩니다. 이미 만료된 세션의 복구에는 재로그인이 필요합니다.

세션 자동 연장이 켜져 있으면 지원 브라우저에서 매분 업무포털·나이스·K-에듀파인 탭의 백그라운드 실행 상태를 활성화한 뒤 각 시스템의 공식 연장 상태를 확인합니다. 이 동작은 브라우저 창을 앞으로 가져오거나 업무 화면을 새로고침하지 않습니다. 연장 성공은 서버 응답으로만 판정하며, 응답이 없는 동안 세션 유지가 보장되지는 않습니다.

## 상단 슬라이드 MVP (2026-09-30)

- 시작 시 화면 상단에 `▼ 업무포털` 손잡이만 표시합니다. 클릭하면 기존 2행 조작창이 약 180ms 동안 내려옵니다.
- `▲ 접기` 또는 포털/손잡이에 포커스가 있을 때 Esc로 접습니다. 마우스를 올리기만 해서는 열리지 않습니다.

- 트레이 우클릭의 `상단 슬라이드 모드 (MVP)`를 해제하면 일반 창으로 돌아옵니다. 이번 MVP는 재실행 시 상단 모드로 시작합니다.
- 상단 모드에서는 항상 위 표시를 강제합니다. 전체 화면 앱에서도 손잡이가 남을 수 있으며 자동 숨김은 아직 구현하지 않았습니다.
